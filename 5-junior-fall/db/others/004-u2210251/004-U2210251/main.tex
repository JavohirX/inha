\section{2nd section}
\subsection*{What is a database view?}

A view is any relation that is not of the conceptual model but is made visible to a user as a ``virtual relation''. A view only stores the SQL query; it does not contain actual data. When it is used in a query, the view is substituted into the SQL query it stores.
\subsection*{2.1 What are some advantages views have over base tables?}

\begin{enumerate}
    \item \textbf{Security:} Views can limit access to specific data in the underlying tables.
    \item \textbf{Simplified Queries:} Views allow saving complex queries as virtual tables, making it easier to reuse these queries without needing to rewrite them each time.
    \item \textbf{Data Abstraction and Independence:} Views provide a level of abstraction, allowing changes to the underlying table structure without impacting applications that rely on the view.
\end{enumerate}

\section{3rd section}
\subsection*{3.1 What is a primary key? What characteristics does a good primary key have?}

A primary key is a minimal superkey, that is, a set of one or more attributes whose values are guaranteed to identify tuples in the relation uniquely, but none of whose subsets is a superkey.

\textbf{Characteristics of a good primary key:}
\begin{enumerate}
    \item \textbf{Uniqueness:} Each value in the primary key column or columns must be unique.
    \item \textbf{Non-Null:} A primary key cannot contain NULL values.
    \item \textbf{Constant:} A primary key should not change over time.
    \item \textbf{Minimal:} A primary key should be as simple and contain minimal columns as possible.
\end{enumerate}

\section{4th section}
\subsection*{4.1 Describe at your best major similarities and differences between a WHERE clause and a HAVING clause in SQL standard.}

\textbf{Similarities:}
\begin{enumerate}
    \item \textbf{Filtering Data:} Both WHERE and HAVING clauses are used to filter the rows returned in a query based on specific conditions.
    \item \textbf{Use in SELECT Statements:} Both clauses are commonly found in SELECT statements.
    \item \textbf{Combine with Conditions:} Both support conditions using operators like =, <, >, IN, and logical operators (AND, OR, NOT).
\end{enumerate}

\textbf{Differences:}
\begin{enumerate}
    \item \textbf{Filtering Order:} WHERE clause filters rows before any grouping or aggregation, whereas HAVING filters groups or aggregated results after grouping.
    \item \textbf{Usage Scope:} WHERE clause filters individual rows, while HAVING is used to filter based on aggregated values.
    \item \textbf{Grouping Relation:} WHERE is used before GROUP BY, in contrast, HAVING is used after GROUP BY.
    \item \textbf{Applicability:} HAVING can be used in any SELECT statement with aggregation, whereas WHERE can be used in SELECT, UPDATE, and DELETE statements.
    \item \textbf{Aggregate Functions:} Unlike WHERE, HAVING can use aggregate functions (like SUM, COUNT).
\end{enumerate}

WITH StudentFailCount AS (
    SELECT ID, COUNT(*) as f_count
    FROM takes
    WHERE grade = 'F'
    GROUP BY ID
    HAVING COUNT(*) >= 2
)
SELECT 
    t.ID,
    s.name,
    t.course_id,
    c.title as course_title,
    t.semester,
    t.year,
    t.grade
FROM StudentFailCount sfc
JOIN takes t ON sfc.ID = t.ID
JOIN student s ON s.ID = t.ID
JOIN course c ON c.course_id = t.course_id
WHERE t.grade = 'F'
ORDER BY t.ID, t.year, t.semester;

DELIMITER //

CREATE PROCEDURE TransferFunds()
BEGIN
   
    CREATE TABLE IF NOT EXISTS account1 (
        account_id INT PRIMARY KEY,
        balance DECIMAL(10, 2) NOT NULL CHECK (balance >= 0)
    );

    CREATE TABLE IF NOT EXISTS account2 (
        account_id INT PRIMARY KEY,
        balance DECIMAL(10, 2) NOT NULL CHECK (balance >= 0)
    );

    
    START TRANSACTION;

    
    UPDATE account1
    SET balance = balance - 1000
    WHERE account_id = 1 AND balance >= 1000;

    
    IF ROW_COUNT() = 1 THEN
       
        UPDATE account2
        SET balance = balance + 1000
        WHERE account_id = 2;

        
        COMMIT;
    ELSE
        
        ROLLBACK;
    END IF;
END //

DELIMITER ;

-- xii. TIMEDIFF (Date & time function; Subtract time)
SELECT time_slot_id,
       TIMEDIFF(
           CONCAT(end_hr, ':', end_min),
           CONCAT(start_hr, ':', start_min)
       ) as duration
FROM time_slot;

\begin{lstlisting}
-- xv. CURRENT_TIME (Date & time function; Return the current time)
SELECT time_slot_id,
       CASE 
           WHEN CURRENT_TIME() BETWEEN 
               CONCAT(start_hr, ':', start_min) AND 
               CONCAT(end_hr, ':', end_min)
           THEN 'Current'
           ELSE 'Not Current'
       END as slot_status
FROM time_slot;
\end{lstlisting}
